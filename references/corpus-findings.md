# 本地优秀论文语料的观察结果

## 证据范围

本 Skill 基于工作区内 2017–2023 年中国研究生数学建模竞赛优秀论文整理而成。语料共 278 篇 PDF，按年份分布为 39、38、30、39、32、42、58 篇；按 A–F 题分布为 44、53、46、46、44、45 篇。PDF 页数范围 10–138 页，均值约 54.97 页。

分析采用两层抽样：

1. 对 278 篇论文的前 6 页与末 2 页做全量文本统计，用于观察摘要、首尾结构和高频方法；
2. 按“年份 × 题型”分层选取 42 篇代表论文做全文结构与方法词检查，并对 2023 年 A、C、F 题样本的摘要页、模型页和网络结构页做视觉核验。

限制：PDF 文本抽取会受扫描、字体编码、目录重复和公式拆分影响；方法词出现不等于它是主模型；“优秀论文”是已筛选样本，没有非优秀论文对照和统一评分，因此下列结果是**优秀论文中的常见做法**，不能被解释为获奖的因果条件。原始 PDF 不随 GitHub 包发布。

## 语料统计观察

### 章节结构

在 42 篇全文分层样本的自动标题识别中，显式出现以下标题或近似标题：

| 结构 | 篇数 | 比例 |
|---|---:|---:|
| 问题重述 | 37 | 88.1% |
| 符号说明 | 35 | 83.3% |
| 附录 | 32 | 76.2% |
| 参考文献 | 30 | 71.4% |
| 模型建立 | 29 | 69.0% |
| 模型假设 | 28 | 66.7% |
| 问题分析 | 27 | 64.3% |
| 模型求解 | 19 | 45.2% |
| 模型评价 | 13 | 31.0% |
| 数据预处理 | 11 | 26.2% |

这些比例是标题识别的下限：有些论文把“检验”“结果分析”合并在问题章节内部，自动抽取不会计为独立标题。更稳定的共性不是固定标题数量，而是“逐问分析—建立—求解—结果/验证”的重复闭环。

### 摘要叙事

42 篇样本的摘要/前言片段中：

| 表达信号 | 篇数 | 比例 |
|---|---:|---:|
| “首先” | 38 | 90.5% |
| “建立” | 38 | 90.5% |
| “求解” | 38 | 90.5% |
| “最后” | 36 | 85.7% |
| “针对问题” | 32 | 76.2% |
| “验证” | 22 | 52.4% |
| “误差” | 21 | 50.0% |
| “指标” | 21 | 50.0% |

这说明优秀摘要倾向于按题目逐问交代过程，并报告求解和验证，而非只介绍背景或罗列模型名。视觉核验还显示，摘要常直接给出关键数值、单位和误差指标。

### 方法生态

42 篇全文样本中，方法词的文档出现频次为：回归 15、神经网络 13、遗传算法 10、机器学习 10、聚类 10、线性规划 9、最短路 9、时间序列 9、模拟退火 8、粒子群 5、微分方程 5、支持向量机 5、交叉验证 5。该分布表明优秀论文覆盖机制、统计、优化、图论、仿真与机器学习，并不存在一个通吃题型的“万能模型”。

在 278 篇前后页统计中，广义优化词出现在 208 篇、评价词 192 篇、决策词 149 篇、预测词 129 篇、统计词 117 篇、仿真词 116 篇。高频不代表复杂模型更优，而是多数赛题最终需要做预测、评价或决策，并把结果转化为可计算目标或指标。

## 写作风格归纳

### 1. 以任务推进，不以模型分类

正文通常按问题一、问题二推进，每一问再组织“分析—建模—求解—结果”。这能让评阅者快速验证是否完成题目要求。仅按“回归模型、优化模型、神经网络模型”分章，容易打断问题链。

### 2. 摘要高度信息化

常见优秀摘要不止写“采用了某模型”，还会说明：为什么选它、获得什么结果、用什么指标与什么对象对照。关键数值通常在摘要中出现，但必须与正文一致。

### 3. 公式、算法、图表相互接力

模型页常先解释约束或机制，再给公式；紧接着给求解方案或结果表；图表之后解释趋势和它如何回答问题。视觉核验的代表样本中，优化约束、求解结果表和下一问分析出现在同一页，衔接紧密。

### 4. 层级清楚但不追求花哨

常见排版是稳定的三级标题、编号公式、三线表、带编号的图和统一符号。可读性来自层次和对齐，而不是装饰色彩。

### 5. 结果语句趋向定量

高质量段落更常使用“指标 + 数值 + 比较对象 + 适用场景”，而不是“效果很好”。当缺乏独立验证时，部分论文仍可能出现证据不足；Skill 将把“结论强度不超过证据”作为额外质量门槛。

## 建模思路归纳

1. **从题目结构出发**：先识别机制、变量、约束和输出，再选方法。
2. **逐问递进**：前一问给出指标、参数或基线，后一问扩展场景、加入约束或改进模型。
3. **解析与仿真互证**：机制类题常用解析模型给解释，再用状态机/蒙特卡洛等仿真核验。
4. **基线与改进对照**：预测或深度学习题往往先给基础网络/方法，再针对明确缺陷加入注意力、多尺度或融合，并比较指标。
5. **优化模型显式化**：把题意转为决策变量、目标函数和约束；求解器或启发式只是求解层，不代替模型本身。
6. **数据驱动前置审计**：缺失、异常、尺度、类别不平衡和数据划分直接决定后续模型是否可信。
7. **结果需回到场景**：把数学输出翻译成吞吐量、成本、风险、路径、排名或政策情景，并说明边界。

## 从语料中提炼出的核心原则

本 Skill 最终采用的主线是：

`题意验收 -> 需求矩阵 -> 问题依赖 -> 基线模型 -> 有依据的增强 -> 求解 -> 与主张匹配的验证 -> 定量解释 -> 结构化写作`

这条主线保留了优秀论文的高频共性，同时补强了语料中并不总是充分呈现的数据泄漏、独立验证、不确定性、约束审计和证据边界。
