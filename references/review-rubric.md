# 数模论文审查量表

## 审查顺序

先做“一票否决项”检查，再评分。不要让语言流畅掩盖模型不可复现或结果无证据。

## 一票否决或高危问题

- 未回答题目中的某一问或缺少指定附件/结果表；
- 目标函数、约束、变量域或边界条件缺失，导致模型不能复现；
- 摘要、正文、表格、代码中的关键数值互相矛盾；
- 使用测试集做训练、特征选择、标准化或反复调参，却声称独立验证；
- 优化结果违反硬约束或单位/时间尺度错误；
- 数据、引用、实验结果、代码运行状态被虚构或无法追溯；
- 公式符号未定义或一符多义，导致关键推导无法判断；
- 把相关性直接写成因果性，或把情景假设写成确定预测；
- 附录代码与正文模型不是同一个实现；
- 图表无法辨认、轴或单位缺失，关键结论仅依赖不可读图形。

## 100 分量表

分数用于定位短板，不代替竞赛官方标准。

### A. 任务覆盖与问题分析（15）

- 0–5：逐问输出和范围是否明确；
- 0–4：问题之间的依赖是否正确；
- 0–3：核心矛盾和难点是否抓准；
- 0–3：论文结构是否能映射到题目要求。

### B. 模型合理性与数学完整性（25）

- 0–6：模型选择有结构依据，复杂度适当；
- 0–6：变量、目标、约束/方程和参数完整；
- 0–4：假设必要、合理且影响可解释；
- 0–4：单位、维度、边界、变量域一致；
- 0–5：各模型构成闭环而非方法堆砌。

### C. 数据与计算可复现性（15）

- 0–4：数据来源、范围、字段、单位清楚；
- 0–4：缺失、异常、编码、缩放处理可复现；
- 0–4：算法、初始化、超参数、停止条件明确；
- 0–3：代码、表格、公式和文本口径一致。

### D. 结果、验证与稳健性（25）

- 0–6：结果直接回答题目且单位/场景完整；
- 0–6：有合理基线或解析/实测对照；
- 0–5：评价指标匹配任务，数据划分无泄漏；
- 0–4：敏感性、不确定性或误差分析针对关键风险；
- 0–4：失败案例、适用边界和代价得到讨论。

### E. 论文叙事与表达（15）

- 0–4：摘要覆盖方法、结果和验证；
- 0–4：章节按问题链推进，前后衔接清楚；
- 0–3：公式前有动机、图表后有解释；
- 0–2：术语、符号、语法和格式统一；
- 0–2：结论强度不超过证据。

### F. 创新与推广（5）

- 0–3：创新解决了明确缺陷，并有消融/比较或理论解释；
- 0–2：推广说明可迁移部分、需重估参数和边界。

## 等级解释

- 90–100：闭环完整，可进入格式和措辞精修；
- 80–89：主体可靠，仍有少量验证或叙事缺口；
- 70–79：可读但存在明显技术短板，应先修模型/验证；
- 60–69：关键链条不完整，语言润色收益有限；
- 60 以下：需重新梳理题意、数学表述或计算证据。

若存在高危问题，即使总分较高，也应先标为“未就绪”。

## 审查输出格式

### 1. 就绪度结论

一句话说明当前最主要的阻碍，以及属于题意、模型、计算、验证还是写作问题。

### 2. 问题清单

每条使用以下结构：

- **位置**：章节、公式、图表或页码；
- **级别**：P0 致命 / P1 高 / P2 中 / P3 低；
- **证据**：原文、公式、数值或缺失项；
- **影响**：为什么会削弱结论；
- **修改**：可以直接执行的修复步骤；
- **复核**：修改后用什么指标或检查确认。

### 3. 分项评分

列出 A–F 分数和一句证据，不给无依据的印象分。

### 4. 修复顺序

推荐顺序：题意遗漏 -> 数据/口径 -> 数学模型 -> 代码/求解 -> 验证 -> 图表 -> 摘要和语言。

### 5. 可直接替换的文字

只对技术事实已经稳定的段落给出替换稿；对仍需计算或核实的地方保留明确占位符。

## 快速自检清单

- [ ] 每问都存在明确最终答案；
- [ ] 摘要中的模型、数字、指标能在正文定位；
- [ ] 所有变量、单位和索引一致；
- [ ] 权重、阈值、参数和超参数有来源；
- [ ] 训练/验证/测试或仿真/解析对照清楚；
- [ ] 优化解通过约束审计；
- [ ] 至少一个有意义的基线；
- [ ] 关键主观参数经过扰动；
- [ ] 图表标题、轴、图例、单位完整；
- [ ] 结论包含范围和限制；
- [ ] 参考文献与文内引用对应；
- [ ] 附录代码能映射到正文算法。
