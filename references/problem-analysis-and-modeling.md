# 问题分析与建模方法

## 1. 先把自然语言变成可验收任务

逐问建立“要求—输出—证据”矩阵。若题目中的动词不同，交付物也不同：

| 题目动词 | 必须交付 | 常见漏项 |
|---|---|---|
| 分析/解释 | 影响方向、大小、机制与证据 | 只做相关图，不解释条件和混杂因素 |
| 预测 | 点预测或概率、区间、误差、外推范围 | 训练集拟合好就声称预测有效 |
| 评价/排序 | 指标体系、方向、权重、排序稳定性 | 权重来源不清，正负向指标弄反 |
| 优化/设计 | 决策变量、目标、约束、可行解、比较基线 | 只给算法，不给数学规划模型 |
| 仿真 | 状态、转移规则、参数、重复次数、收敛性 | 单次随机结果当作结论 |
| 制定策略 | 触发条件、行动、代价、风险和适用边界 | 建议与前文模型输出脱节 |
| 证明/推导 | 前提、推导链、边界或反例 | 跳步或以数值例子代替证明 |

把模糊词转为指标。例如“效果最好”必须明确是误差最小、收益最大、风险受限、鲁棒性最好，还是多目标折中。

## 2. 建立跨问题依赖图

为每一问写成：

`原始输入 -> 中间变量 -> 本问模型 -> 本问输出 -> 后续用途`

重点检查：

- 后一问是否把前一问的估计值当作无误差真值；
- 同一变量在不同问中是否换了含义、单位或时间尺度；
- 是否存在“先用最终标签筛特征，再划分训练集”的信息泄漏；
- 多场景或多阶段问题是否保持约束、口径和基准一致；
- 是否有本应联合求解却被人为分开、导致局部最优的变量。

## 3. 识别题型并选择模型族

先看数学结构，再看熟悉程度。表中“增强模型”只有在基线暴露出对应缺陷后才启用。

| 结构信号 | 透明基线 | 可选增强 | 至少需要的验证 | 高发风险 |
|---|---|---|---|---|
| 连续量预测、解释影响 | 线性/广义线性回归、简单时间序列 | 正则化、树模型、核方法、神经网络 | 时间或分层划分、残差、基线、区间 | 随机打乱时序、把相关当因果 |
| 分类/概率 | 逻辑回归、朴素规则 | 树模型、SVM、神经网络 | 混淆矩阵、AUC/PR、校准、类别不平衡 | 只报准确率、阈值由测试集反复调 |
| 资源分配/调度 | 线性或整数规划 | 非线性、多目标、分解、启发式 | 可行性、最优间隙/界、基线、敏感性 | 漏约束、罚函数替代硬约束无说明 |
| 路径/网络 | 最短路、最小生成树、网络流 | 车辆路径、时空网络、元启发式 | 路径可行、复杂度、与下界或基线比较 | 距离矩阵不对称却按对称处理 |
| 综合评价/排序 | 标准化加透明权重 | AHP、熵权、TOPSIS、PCA、组合赋权 | 指标方向、权重扰动、秩相关、稳定区间 | 重复指标、权重伪客观、量纲错误 |
| 物理/生物/通信机制 | 守恒方程、差分/微分方程、状态机 | 随机过程、有限元、耦合模型 | 量纲、边界条件、极限情形、观测/仿真对照 | 机理参数无来源、数值解未做收敛检查 |
| 随机过程/系统运行 | 解析概率、排队/马尔可夫 | 蒙特卡洛、离散事件、代理模型 | 重复次数、置信区间、解析或实测对照 | 用单次随机轨迹下结论 |
| 图像/时空高维数据 | 统计特征加简单模型 | CNN、UNet、RNN、GNN、融合模型 | 数据划分、消融、外部或场景验证、资源说明 | 样本少却堆深网、无消融、切片泄漏 |
| 多因素情景决策 | 情景枚举、规则模型 | 鲁棒/随机优化、系统动力学 | 情景覆盖、关键参数敏感性、最坏情形 | 把情景设定写成预测事实 |

## 4. 构造“基线—缺陷—增强”论证

每次增加复杂度都写三句话：

1. 基线是什么，它回答了什么；
2. 哪个诊断结果暴露了什么缺陷；
3. 增强模型具体修复哪个缺陷，以哪个指标验证。

若第三句没有可测指标，就不应添加该模型。多个模型并列时说明它们是竞争、串联还是集成关系，避免把方法清单误写成建模思路。

## 5. 数学表述最低要求

### 优化模型

必须显式给出：

- 决策变量及其类型，如连续、整数、0-1；
- 目标函数及业务含义；
- 每一类约束和物理/业务含义；
- 参数来源、尺度与单位；
- 可行性、求解器、最优性或停止准则；
- 多目标模型的归一化、权重或 Pareto 处理。

### 预测或统计模型

必须显式给出：

- 目标变量定义和预测时点；
- 特征在真实使用时是否可获得；
- 训练、验证、测试划分原则；
- 缺失、异常、编码、缩放仅在训练数据上拟合；
- 参数/超参数选择过程；
- 与任务一致的评价指标及基线；
- 不确定性、残差或错误样本分析。

### 机理/动态模型

必须显式给出：状态变量、控制量、参数、守恒或转移方程、边界/初始条件、数值离散、稳定性/收敛性检查，以及参数识别方法。

### 评价模型

必须显式给出：指标筛选逻辑、正负向、单位、归一化、权重来源、聚合规则、排名/分档规则，以及权重与数据扰动下的稳定性。

## 6. 数据处理要服务于模型假设

推荐记录一张数据审计表：字段、类型、单位、时间/空间粒度、缺失机制、异常规则、处理方法、处理前后样本数、是否参与标签构造。

常见检查：

- 重复样本、编码错误、单位混用、日期错位；
- 缺失是否随机，插补是否使用了未来信息；
- 异常是测量错误还是关键极端事件；
- 空间邻近、同一对象重复观测造成的数据相关性；
- 类别不平衡和评价指标选择；
- 归一化参数是否仅由训练集得到。

## 7. 匹配验证方法与结论

| 结论类型 | 证据组合 |
|---|---|
| “预测更准” | 独立测试/滚动验证 + 合理基线 + 多指标 + 误差分布 |
| “方案更优” | 约束全满足 + 同口径目标比较 + 计算代价 + 参数/权重敏感性 |
| “模型合理” | 量纲/边界/极限检查 + 实测或解析对照 + 残差/误差解释 |
| “排序稳定” | 权重扰动 + 数据扰动/重采样 + 秩相关或名次区间 |
| “机制有效” | 对照或消融 + 中间变量证据 + 替代解释讨论 |
| “可推广” | 外部场景、留一地区/年份、参数可迁移性或明确适用边界 |

不要把灵敏度分析写成固定仪式。优先扰动对结论最有影响、来源最不确定或由作者主观设定的参数。

## 8. 算法与实现说明

算法段落至少回答：输入是什么、如何初始化、每一步更新什么、何时停止、输出什么、复杂度或规模瓶颈是什么。若使用随机算法，报告随机种子策略和多次运行稳定性；若使用商用求解器，报告关键配置和最优间隙；若使用深度学习，报告数据划分、网络输入输出维度、损失、优化器、训练轮数与早停。
