# 使用手册

## 1. 输入材料怎么给

### 仅有题目时

提供完整赛题、附件字段说明、竞赛限制和期望工具。Skill 将先输出需求矩阵、依赖关系和待确认项，再设计模型链。

### 已有数据时

同时提供字段、单位、样本范围、缺失说明和文件路径。若允许读取文件，应要求先做数据审计，不要直接训练复杂模型。

### 已有代码时

说明代码入口、运行环境和当前错误/结果。要求核对“正文模型—代码实现—输出表格”一致性。

### 已有论文时

说明需要：结构审查、技术审查、语言润色、摘要重写、图表改进或最终校对。整篇修改建议保留原稿并输出新文件及位置化修改清单。

## 2. 五种工作模式

### 问题分析模式

适用于刚拿到题目。输出包括核心冲突、逐问需求矩阵、问题依赖、候选模型链、数据计划、验证计划和论文提纲。

### 模型设计模式

适用于已确定题意但需要数学方案。每一问应包含变量、公式/目标/约束、参数来源、求解算法、输出、验证、敏感性和局限。

### 论文架构模式

适用于模型已有但文章混乱。重点检查每个题目要求是否有章节承载，以及每一问是否形成闭环。

### 写作润色模式

适用于段落或全文表达改进。Skill 不应静默改变数值、术语含义和因果强度；技术问题应作为批注暴露。

### 全文审查模式

适用于提交前。先查致命问题，再用 100 分量表定位短板，最后给修复顺序。高危问题未清除时，不应优先做表面润色。

## 3. 推荐的多轮协作

### 第一轮：验题

只做需求矩阵和依赖图，确认每问输出与限制。

### 第二轮：定模型

比较 2–3 条候选模型链，明确基线、增强条件、数据要求和验证成本。

### 第三轮：算与验

实现模型、记录参数与结果，完成基线、残差/误差、约束、敏感性或消融检查。

### 第四轮：搭架构

把计算证据映射到摘要、各问、图表、结论和附录。

### 第五轮：审稿与润色

先修技术问题，再统一术语、句式、图表和排版。

## 4. 如何判断输出是否靠谱

至少检查：

- 推荐模型是否对应题目结构，而非因为流行；
- 是否说明了更简单基线及其不足；
- 数值是否来自实际计算；
- 预测划分是否防止泄漏；
- 优化结果是否通过硬约束检查；
- 评价权重是否有来源并做扰动；
- 结论是否包含比较对象、指标、单位和范围；
- 摘要是否能在正文逐项找到证据。

## 5. 与模板配合

[论文模板](../assets/contest-paper-template.md) 用于快速搭架构。它不是固定格式：短论文可以合并假设与符号；复杂数据题可以提前设置数据章节；机制题可把局部假设放在方程之前。

## 6. 常见误用

- 要求“一步生成完整高分论文”，但没有真实计算；
- 用多个模型名替代建模逻辑；
- 先看测试集再调特征和阈值；
- 把灵敏度分析当作形式化加减 10%；
- 让润色工具把不确定结论改成确定结论；
- 把附件代码堆入附录，却不在正文说明输入输出和调用关系。
